# EDL-208 learning note

EDL-208 adds the first `kilnd` process. The resolved EDL-200 and EDL-202
decisions define its crate and protocol boundaries.

This slice follows the
[architecture map](../architecture/architecture.yaml),
[target monorepo](../architecture/target-monorepo.yaml), and
[local client perimeter](../architecture/perimeter.md). The generated
[protocol reference](../../protocol/generated/reference.md) records the
implemented HTTP and WebSocket surface.

## Ownership

`kiln-protocol` owns the canonical public Rust DTOs and generated contract
files. `kiln-core` owns process-independent store metadata. It has no Axum,
Serde, or protocol dependency. `kiln-server` maps core values to protocol
responses and owns HTTP and WebSocket transport. `kiln-daemon` binds loopback
and composes the core value with the server.

## Rust patterns

`AppState::from_core` takes ownership of `StoreMetadata`. Axum clones the state
for a request. The negotiation handler then constructs a protocol
`StoreIdentity` explicitly. This keeps core types out of the public wire
contract.

Enums make the WebSocket transport frame set explicit. Exhaustive `match`
handling makes ping, close, text, and binary behavior visible. Serde controls
the snake_case JSON contract. Command types reject unknown fields. Response
types ignore unknown fields so a client can read a compatible response that
adds data.

The current cursor uses `Option<String>` because a new store has no Event yet.
The field is still present on the wire. A schema-only marker records it as
required and nullable. This keeps "missing" different from `null`.

`PublicError` is a typed server error. Its exhaustive `match` maps each internal
case to a stable status and code in the protocol-owned `ProblemDetails` DTO.
Framework rejection text does not cross the public boundary.

The generated OpenAPI, JSON Schema, TypeScript, catalogue, fixtures, and
reference files are derived from the Rust protocol types. A test compares every
stored artifact with the generator output.
