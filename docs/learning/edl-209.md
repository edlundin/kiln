# EDL-209 Rust learning note

This slice adds the first durable Kiln aggregate. A `Workspace` owns one or
more ordered `WorkspaceRoot` values. `WorkspaceId` and `WorkspaceRootId` are
newtypes, so code cannot exchange the two identifiers by accident. Their wire
values are opaque prefixed ULIDs. The database primary keys make a duplicate
identifier fail instead of replacing existing state.

The aggregate constructor protects its invariants. It rejects an empty root
list, empty names, duplicate root names, and duplicate Git common-directory
paths. Fields stay private outside `kiln-core`; read-only accessors expose only
valid state. The application operation validates all labels before it starts
Git discovery. It calls persistence only after every root is valid.

Two core traits mark real side-effect boundaries:

- `WorkspaceRootDiscovery` asks for canonical Git identity.
- `WorkspaceStore` writes and reads a complete aggregate.

The traits return `Send` futures because the Axum server can move a request
future between Tokio worker threads. The concrete application uses static
dispatch. Kiln does not need a trait object or `async-trait` for this slice.

`kiln-infrastructure` implements both boundaries. Git commands discover the
worktree top level and Git common directory. Kiln stores the user path as
display data, but it compares canonical common-directory paths for repository
identity. SQLx runs an embedded migration. One SQLite transaction inserts the
Workspace and all roots. If any insert fails, dropping the transaction rolls
back all prior inserts.

The server performs explicit conversion between public protocol DTOs and core
types. This keeps JSON compatibility rules out of the aggregate and keeps
domain fields out of the public contract by accident. The daemon creates the
Git adapter, SQLite store, ID generator, application operation, and server.

The forbidden dependency edges are:

- `kiln-core` does not depend on Axum, SQLx, SQLite, Git, or `kiln-protocol`.
- `kiln-protocol` does not depend on core, Axum, or SQLx.
- `kiln-infrastructure` depends on core, but core does not depend on it.
- `kiln-server` maps protocol and core values but does not access SQLx.
- clients use HTTP and WebSocket and do not import core internals.

The real-daemon test creates two Git repositories, creates a Workspace through
HTTP, restarts `kilnd` with the same temporary data directory, and retrieves
the same IDs and root order. Focused tests cover aggregate rejection, Git
identity, migrations, and transaction rollback.
