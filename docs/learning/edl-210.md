# EDL-210 Rust learning note

This work adds a durable `Session` to Kiln. A Session stores one
`WorkspaceId`. It does not store a worktree, repository path, or branch. A
worktree can disappear without deleting the Session history.

The client sends commands. It does not insert domain Events. Creating a
Session emits `session.created`. Appending immutable user content creates one
`Message` and emits `message.appended`. Core enums make the accepted Event
shapes explicit. An unsupported shape cannot enter the domain through a free
form event type string.

`SessionId`, `MessageId`, and `EventId` are different Rust newtypes. Their wire
values use the `ses_`, `msg_`, and `evt_` prefixes with canonical ULIDs. The
prefixes help a person identify a copied value. The newtypes stop code from
using one identity where another identity is required.

An Event ID identifies one Event. It does not define the durable replay order.
SQLite assigns a daemon-wide numeric commit cursor when it inserts an Event.
The cursor is an opaque decimal string in the public protocol. This avoids
JavaScript integer precision problems and lets Kiln change its internal cursor
representation later.

The global cursor does not schedule work and does not add FIFO execution
between Sessions. It only records the commit order of durable audit records.
An Event query filters one Session and keeps the global cursor values, so gaps
between returned values are valid.

Session creation writes the Session and `session.created` in one SQLite
transaction. Message append writes the Message and `message.appended` in one
transaction. A failed Event insert rolls back the state row. A client can
therefore never observe accepted state without its matching audit Event.

An Event query reads the matching rows and the current global cursor from one
SQLite snapshot. This prevents a race where the response cursor could move
past an Event that was not included in the response.

The core defines Session operations and storage traits with core values only.
The SQLite adapter owns SQL rows, transactions, and cursor allocation. The
server converts between protocol DTOs and core types. The daemon shares one
SQLite adapter between the Workspace and Session applications.

This release adds no paging limit. There is no measured workload that supports
one. Runs, tools, WebSocket Event publication, message cancellation,
attachments, and worktree presentation remain outside EDL-210.
