# EDL-212 Rust learning note

EDL-212 makes starting a Run safe to retry. `POST /v1/sessions/{session_id}/runs`
requires a non-empty opaque `Idempotency-Key` header. The key is unique for the
start-run operation and Session. SQLite stores the key with the original Run.

The Run row, its `run.created` Event, and the idempotency result use one
transaction. A duplicate key returns the original Run snapshot and an explicit
`Duplicate` disposition. The daemon dispatches a subprocess only for the
`Created` disposition. A different key still receives the active-root conflict
while the original Run is queued or running.

The global event port reads every durable Event after an exclusive cursor and
returns the result and high-water cursor from one SQLite read transaction.
Global replay keeps each selected Event. Cursors are opaque ordering values;
they do not need to be numerically contiguous.

The event WebSocket subscribes before its durable snapshot. An `after` cursor
gets an acknowledgement followed by the exact durable suffix through that
snapshot boundary. Later broadcaster messages are wake-up signals only. Each
wake queries SQLite after the last sent cursor, so durable cursor order remains
authoritative. Without `after`, the connection keeps its existing live-only
snapshot behavior.
