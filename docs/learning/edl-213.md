# EDL-213 Rust learning note

EDL-213 adds durable Run cancellation and graceful daemon shutdown. A client
sends `POST /v1/runs/{run_id}/cancel`. Kiln first commits
`run.cancellation_requested` and the `cancelling` Run state. It then stops the
owned subprocess group, collects its output, and commits terminal `cancelled`
ToolCall and Run states. A repeated request returns the same terminal Run.

Completion and cancellation use one durable ordering rule. The operation that
commits first wins. If completion commits first, cancellation returns the
completed Run. If cancellation commits first, later executor completion cannot
replace it.

The Unix adapter starts each managed subprocess in a new process group. A
signal to the negative process-group ID reaches the direct child and normal
descendants. An RAII guard implements `Drop`, so an abandoned execution future
also stops its group. This ownership does not include a descendant that leaves
the group with `setsid` or a process-group change.

The daemon uses a Tokio one-shot channel to request cancellation and a watch
channel to share the final result with concurrent callers. The active-Run map
keeps the cancellation sender and shared result. It removes an entry only after
the terminal snapshot is durable.

SIGINT and SIGTERM move the server lifecycle to `quiescing`. New mutating
commands then receive `daemon_shutting_down`. Accepted commands can finish
their commit sections. The daemon cancels active Runs in parallel and closes
storage only after all terminal results are durable. Read-only requests remain
available while the server drains. There is no HTTP shutdown command until
Kiln has local authentication for privileged routes. If execution or terminal
persistence fails, Kiln removes the dead execution from the active registry,
reports shutdown failure, and keeps the process and storage open for a forced
stop or recovery.
