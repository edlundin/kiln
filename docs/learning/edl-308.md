# EDL-308 attachment continuation

30 September 2026. Tested baseline: `9dfb590ebf7649e6ff442b5d8bb66f850a0c0fef`
plus this uncommitted attachment patch. EDL-308 remains open because native
drag/drop and image/file clipboard acceptance is incomplete.

## Changes

Adding a second attachment reproduced a debug desktop crash in GPUI's
accessibility tree: `Duplicate a11y node id`. Retry and Remove now have distinct
IDs and file-specific accessible names. Native two-file selection and recovery
subsequently completed without that crash.

Picker results are bound to the original Session and event-stream generation.
File opens use `NOFOLLOW`, `NONBLOCK` and `CLOEXEC`, followed by a regular-file
descriptor check. Draft attachment edits cannot mutate an in-flight, appended
or uncertain message; direct file drops also respect in-flight/session-switch
guards. Existing storage migrations and attachment validation are reused.

The focused daemon scenario passed: 1 passed, 0 failed, 24 filtered, 2.55 seconds.
Desktop build/packaging passed, with the existing `block v0.1.6`
future-incompatibility advisory. Native interaction used the built-in computer
use integration after the TypeSafe CLI reported an unavailable text writer.

Initial fixture compilation used incorrect protocol identifiers and SHA-256
formatting; those were corrected. Runtime fixture corrections wait for durable
approval Events rather than assuming the immediate Run response is terminal,
and use abrupt restart because graceful shutdown intentionally cancels pending
work. A full oversized upload initially produced a connection reset while the
server rejected its unread body; the final size-error assertion checks early
Content-Length rejection. Chunked oversized uploads were not separately tested.

No broad suite, commit, staging, push or Linear mutation was performed. Temporary
native app/daemon processes were stopped after inspection. Unrelated worktree
changes were preserved.
