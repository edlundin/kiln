# EDL-314 — native MCP form acceptance

Issue: <https://linear.app/edlundin/issue/EDL-314>

## 1 October 2026 continuation

Form choices and optional-field controls used GPUI `Button::selected` alone.
In the pinned `gpui-component` 0.6.1 source, that setting changes presentation;
it deliberately does not imply accessibility toggle state. The controls now also
set `Button::toggled` from the same selection, exposing true and false pressed
states without changing the form content or decision behavior. This is a
source-confirmed accessibility repair. Native screen-reader acceptance remains
unverified.

| Acceptance condition | Result | Evidence and limits |
| --- | --- | --- |
| Accessible choice and optional-field selection state | **pass** for source/API integration; **blocked/unverified** for native acceptance | Both controls set `toggled` alongside `selected`; the pinned component maps it to GPUI `aria_toggled`. The desktop builds. No native accessibility tree was obtained. |
| Authenticated form resolution through a real stdio server | **pass** for the exercised API boundary | The existing mixed native batch fixture held its form open for a desktop acceptance attempt. Authenticated inspection and an explicit `{"proceed":true}` decision resolved the input; public Events contained neither the form message nor schema. The fixture completed all normal ToolCalls, artifact paging, one external effect and completed-batch no-replay checks. No real credentials or external provider were used. |
| Native loading, validation, keyboard, reconnect and submission | **blocked/unverified** | The macOS bundle launched. Temporary startup diagnostics reported successful window creation, but native automation returned `cgWindowNotFound`. The installed TypeSafe inspector captured T3 Code instead of Kiln, so that capture is not acceptance evidence. |

Checks run:

- `rtk proxy cargo test -p kiln-daemon --bin kilnd --no-run --message-format=json` built a temporary manual-acceptance variant of the existing fixture. Its compiled test binary ran `run_service::native_mcp::tests::mixed_native_batch_waits_for_approval_completes_and_never_replays --exact --nocapture`: 1 passed, 15 filtered, 472.47 s including the manual wait. The temporary variant held the authenticated server open and used a 15-minute interaction budget only for this attempt; it introduced no production allowance. Initial fixture compilation failed because an API path shadowed the repository path; that temporary error was corrected before the successful build.
- `rtk proxy cargo build -p kiln-desktop --bin kiln-desktop`: passed after the selection-state repair, 10.08 s. Existing `block v0.1.6` future-incompatibility advisory remains.
- `rtk proxy sh apps/desktop/package-macos.sh`: passed for the acceptance launch. Temporary startup diagnostics and manual fixture source changes were restored; owned processes were stopped.

The fixture client initially expected a separate `recorded` public Event. Actual
Events were `required` followed by `resolved`; the explicit decision returned
`applied:true`. That expectation was corrected without changing product code.
These checks do not establish URL elicitation, sampling, official conformance,
real vault access or native interaction acceptance.
