# EDL-322 — two-instance configuration acceptance

Issue: <https://linear.app/edlundin/issue/EDL-322>

## 1 October 2026 continuation

Two fresh loopback daemons exercised the existing local administration APIs,
pinned TLS transport and real macOS Keychain adapter. The fixture used only
generated test identities and one follower credential; no existing account,
credential or database was accessed. The published revision was an empty shared
bundle, so this does not establish model, MCP or skill consumer acceptance.

The approved follower response exposed a native wording defect: its preparation
phase is `retired` while its separately journaled credential remains active.
Settings called that enrollment **Retired** and offered only **Retry credential
cleanup…**, suggesting that retirement had already happened. It now says
**Preparation closed**, explains that approval can retain a credential, and
offers **Retire enrollment / retry cleanup…**. The API, vault lifecycle and
confirmation behavior are unchanged. Historical approval never becomes a claim
that the credential or remote grant is currently active.

Checks run:

- The disposable Python fixture ran through `rtk proxy python3` using the
  existing authenticated local routes for designation, identity setup/export,
  publication, preparation/exchange, exact approval, fetch, revocation and
  retirement. Both daemons were launched directly from the built `kilnd`.
  TLS certificate validation stayed enabled, using the exported and
  fingerprint-checked CA; the follower used Kiln's pinned client.
- The listener allowed one connection and one retained request, matching this
  serial, single-enrollment workload. Its 8192-byte HTTP buffer is the supported
  minimum; explicit five-second handshake/request/shutdown allowances match the
  existing small local fixtures. These are acceptance inputs, not defaults.
- `rtk proxy cargo build -p kiln-desktop --bin kiln-desktop`: passed after the
  wording repair, 12.38 s; existing `block v0.1.6` advisory remains.
- `rtk proxy rustfmt --edition 2024 --config skip_children=true --check apps/desktop/src/follower_enrollment.rs` and `rtk proxy git diff --check`: passed after correcting the new tuple's formatting.

The temporary HTTP wrapper initially assumed every success returned JSON. Grant
revocation correctly returned an empty 204 response; the wrapper was corrected
and a GET confirmed the committed revocation before continuing. No product
change was needed for that fixture error. No secret bytes or private vault
references were printed or retained in the acceptance report.

Nonempty shared settings, runtime consumers, background refresh, abnormal
cancellation/expiry/role-loss, non-macOS behavior and native acceptance remain
