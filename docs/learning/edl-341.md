## Settings scroll continuation

The native investigation confirmed a layout cause behind the inaccessible
provider section. The scroll container is a horizontal flex row used to center
its content. Its default cross-axis stretch limited the immediate child's height
to the viewport. GPUI computes the scroll extent from immediate child bounds,
so nested overflow did not contribute. Aligning that child at the start preserves
its full content height without changing Settings order or width.

The repaired client scrolled to the provider section and **Sign in with browser**
prepared an isolated account/attempt. At 1060 by 832 pixels, the account summary,
Disconnect and pending Open/Check/Cancel controls were visibly reachable.
**Cancel sign-in** removed the pending actions from the accessibility tree.
Cancellation feedback rendering and the new failure alert remain unverified:
screenshots and accessibility state sometimes diverged until window resize.
This does not establish a general rendering defect or full native acceptance.
The local TypeSafe inspection command completed but captured Zed, not Kiln;
its output supplies no evidence for this acceptance check and was kept temporary.

`rtk proxy cargo build -p kiln-desktop --bin kiln-desktop` passed in 12.03 s;
`rtk proxy rustfmt --edition 2024 --check apps/desktop/src/accounts.rs` and
`rtk git diff --check` passed. The prior daemon tests remain applicable; this
two-line layout repair changes no protocol or backend behavior. No additional
tests were needed. Live OAuth, refresh and OS-vault acceptance remain gated.
